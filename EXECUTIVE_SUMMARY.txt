dependencies on Hyperspatial. It achieves this through a clean trait-based 
abstraction (DataSource) that allows any backend implementation.

INTEGRATION POINT: DataSource TRAIT
================================================================================

Location: src/executor/mod.rs, lines 34-243

The DataSource trait is THE interface between HyperQL and any backend:

pub trait DataSource: Send + Sync {
    // Core operations
    fn scan(&self, table: &str, entity_type: &str) -> Result<Vec<Entity>>;
    fn scan_with_limit(...) -> Result<Vec<Entity>>;  // LIMIT optimization
    fn count_entities_fast(...) -> Result<usize>;    // COUNT optimization
    
    // Data modification
    fn insert(&mut self, table: &str, entities: Vec<Entity>) -> Result<u64>;
    fn update(&mut self, table: &str, filter, assignments) -> Result<u64>;
    fn delete(&mut self, table: &str, filter) -> Result<u64>;
    
    // Schema management
    fn get_schema(&self, table: &str) -> Result<TableSchema>;
    fn create_schema(&mut self, ...) -> Result<()>;
    fn drop_schema(&mut self, ...) -> Result<()>;
    fn alter_schema(&mut self, ...) -> Result<()>;
    fn describe_schema(&self, ...) -> Result<String>;
    
    // Graph traversal
    fn traverse_graph(&self, start_id, max_depth, edge_filter) -> Result<Vec<(Entity, usize)>>;
    
    // Compute integration (for Lua/WASM)
    fn execute_lua_function(&mut self, name, args) -> Result<Value>;
    fn execute_wasm_function(&mut self, module, name, args) -> Result<Value>;
}

Hyperspatial Implementation:

STANDALONE USAGE (Works Without Hyperspatial)

use hyperQL::*;

let mut data_source = MemoryDataSource::new();
data_source.add_entity("users", user_entity);

let statement = parse_statement("SELECT * FROM users WHERE age > 30")?;
let compiled = Compiler::new().compile(statement)?;

let mut executor = Executor::new(Box::new(data_source));
let result = executor.execute(compiled)?;

for row in result.rows {
    println!("{:?}", row);
}

HYPERSPATIAL INTEGRATION (Same Interface)
================================================================================

let router = Arc::new(Router::new("./db")?);
let coordinator = Arc::new(RequestCoordinator::new(router.clone()).await?);

// THIS is the integration point - implement DataSource
let mut data_source = RouterDataSource::new(router, coordinator);

// Everything else is identical to standalone usage
let statement = parse_statement("SELECT * FROM documents")?;
let compiled = Compiler::new().compile(statement)?;
let mut executor = Executor::new(Box::new(data_source));
let result = executor.execute(compiled)?;

pub enum ExecutionPlan {

================================================================================
PERFORMANCE OPTIMIZATIONS
================================================================================

1. Constant Folding
   WHERE age > 20 + 5  →  WHERE age > 25
   Reduces runtime expression evaluation

2. Predicate Pushdown
   Move WHERE clause to data source level
   Example: 100x+ speedup for large datasets

3. Projection Pushdown
   Move SELECT to earlier in execution
   Reduces memory usage in intermediate results

4. Early Termination (scan_with_limit)
   LIMIT optimization at DataSource level
   Example: 60-110x speedup for queries with LIMIT

5. Fast Counting (count_entities_fast)
   COUNT(*) without loading data
   Example: 1000x+ speedup vs scanning all entities

6. Cost Estimation
   CPU and I/O costs tracked through optimization
   Enables better execution strategy selection
